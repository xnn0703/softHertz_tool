## 设备状态显示跳动问题分析与解决方案

### 问题分析

通过分析用户提供的日志和代码，我发现设备状态显示跳动的原因不是实际数据跳变，而是UI更新机制中对`runtime`（运行时间）字段的处理存在问题：

1. **数据来源**：从日志来看，所有天线状态上报帧都解析成功，实际数据没有跳变
2. **字段类型不一致**：
   - `extract_data`方法返回的`runtime`字段是字符串格式，如`"159s"`
   - 但`update_ui`方法假设`runtime`是数字类型，直接使用`int(value)`转换
3. **转换失败导致显示异常**：
   - 当`runtime`是字符串时，`int(value)`转换失败
   - 异常处理将显示设置为`"N/A"`
   - 下次更新时如果是数字，显示恢复正常，导致跳动

### 解决方案

修改`update_ui`方法中对`runtime`字段的处理逻辑，正确处理字符串格式的运行时间：

1. **在`update_ui`方法中**：
   - 专门处理`runtime`字段的字符串格式
   - 提取字符串中的数字部分
   - 确保无论输入类型如何，都能正确显示

2. **修改位置**：
   - 文件：`qt_afd01_qs_ui.py`
   - 方法：`update_ui`
   - 具体位置：处理`runtime`字段的代码段

### 实现步骤

1. **修改`update_ui`方法中的`runtime`字段处理**：
   - 添加类型检查和字符串处理
   - 提取字符串中的数字部分
   - 确保显示稳定，不会在`N/A`和实际值之间跳动

2. **测试修改后的代码**：
   - 验证设备状态显示稳定
   - 确保运行时间等字段正确显示

### 预期效果

- 设备状态显示稳定，不再在老数据和新数据之间跳动
- 运行时间等字段正确显示，不受数据类型影响
- 提高UI显示的可靠性和用户体验

### 关键代码修改

```python
# 原代码
if info_key in ["runtime"]:  # ACU运行时间，以秒为单位，直接显示整数
    display_text = f"{int(value)}s"

# 修改后
if info_key in ["runtime"]:  # ACU运行时间，以秒为单位，处理字符串格式
    try:
        # 处理可能的字符串格式，如"159s"
        if isinstance(value, str):
            # 提取数字部分
            value = int(value.split('s')[0])
        display_text = f"{int(value)}s"
    except (ValueError, AttributeError):
        display_text = "N/A"
```

这个修改确保了无论`runtime`字段是数字还是字符串格式，都能正确显示，避免了显示跳动问题。
