# AFD01_QS设备状态显示修复方案

## 问题分析
经过分析，发现AFD01_QS设备状态显示为"N/A Terminal#0-1008"的问题可能由以下原因导致：

1. **协议解析中的帧长度计算错误**：在`afd01_qs_protocol.py`文件中，完整帧长度计算错误，导致无法正确提取完整帧
2. **数据帧粘包问题**：设备可能发送了粘包数据，导致无法正确解析帧
3. **设备状态信息更新不完整**：某些字段可能没有被正确更新

## 修复方案

### 1. 修复协议解析中的帧长度计算错误
修改`afd01_qs_protocol.py`文件中的`parse_response`方法，将完整帧长度计算从`5 + data_length`改为`6 + data_length`：

```python
# 计算并检查完整帧长度
# 错误：total_frame_length = 5 + data_length  # 帧头(1)+命令(1)+长度(2)+数据(N)+CRC(2)
# 正确：
total_frame_length = 6 + data_length  # 帧头(1)+命令(1)+长度(2)+数据(N)+CRC(2)
```

### 2. 增强数据帧粘包处理能力
修改`afd01_qs_device.py`文件中的`on_received_data`方法，增强粘包处理能力：

```python
def on_received_data(self, data: bytearray):
    """处理接收到的数据，增强粘包处理能力"""
    # 将新数据添加到缓冲区
    self.buffer.extend(data)
    
    # 持续解析缓冲区中的数据，处理可能的粘包情况
    while len(self.buffer) >= 6:  # 最小帧长度：帧头(1)+命令(1)+长度(2)+数据(0)+CRC(2) = 6字节
        # 1. 查找帧头 (0x55)
        frame_start_index = -1
        for i in range(len(self.buffer)):
            if self.buffer[i] == 0x55:
                frame_start_index = i
                break
        
        # 如果没有找到帧头，清空缓冲区并退出
        if frame_start_index == -1:
            self.buffer.clear()
            break
        
        # 如果帧头不在缓冲区起始位置，移除前面的无效数据
        if frame_start_index > 0:
            self.buffer = self.buffer[frame_start_index:]
            continue

```

### 3. 优化设备状态信息更新逻辑
确保`_update_device_info`方法能正确更新所有设备状态字段，`extract_data`方法能正确提取所有设备状态信息，`update_ui`方法能正确更新所有UI标签。

## 修复后预期效果
1. 设备能够正确解析天线状态上报帧，包括粘包数据
2. 设备信息能够被正确更新
3. UI显示的设备状态不再是"N/A Terminal#0-1008"，而是实际的设备状态数据
