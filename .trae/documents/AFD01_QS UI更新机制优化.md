## AFD01_QS UI更新机制优化

### 问题分析
当前AFD01_QS UI的更新机制是每次收到数据信号就立即更新UI，这可能导致UI频繁刷新，影响性能。用户希望将更新频率调整为100ms，只显示最新的数据包。

### 解决方案
1. **修改UI更新机制**：使用QTimer控制UI更新频率
2. **添加数据更新标志位**：记录是否有新数据需要更新
3. **优化信号处理**：收到数据信号时只设置标志位，不立即更新UI
4. **定期更新UI**：定时器每隔100ms检查标志位，如果有新数据则更新UI

### 实现步骤
1. **在__init__方法中添加定时器和标志位**：
   - 添加`self.update_timer`定时器，设置为100ms间隔
   - 添加`self.has_new_data`标志位，初始化为False
   - 连接定时器的timeout信号到更新UI的槽函数

2. **修改_connect_device_signal方法**：
   - 保持信号连接不变，但修改连接的槽函数
   - 新的槽函数只设置`self.has_new_data = True`，不立即更新UI

3. **创建定时更新UI的方法**：
   - 方法名：`_update_ui_periodically`
   - 功能：检查`self.has_new_data`标志位
   - 如果为True，调用`update_ui`方法更新UI，然后重置标志位

4. **修改update_ui方法**：
   - 保持原有逻辑不变，只更新UI显示
   - 不需要添加新功能，只需确保它能正确更新UI

### 预期效果
- UI每100ms更新一次，显示最新的设备状态数据
- 旧的数据不会累积，只会显示最新的数据包
- 减少UI频繁刷新导致的性能问题
- 保持设备状态显示的实时性

### 关键代码修改位置
- `__init__`方法：添加定时器和标志位
- `_connect_device_signal`方法：修改信号处理逻辑
- 新增`_update_ui_periodically`方法：定时检查并更新UI

### 实现细节
- 定时器使用`QTimer.singleShot`或`QTimer.start`实现
- 标志位使用线程安全的方式更新
- 确保在UI关闭时正确停止定时器

这个方案可以有效实现用户需求，将UI更新频率调整为100ms，同时只显示最新的数据包，提高应用程序的性能和用户体验。
