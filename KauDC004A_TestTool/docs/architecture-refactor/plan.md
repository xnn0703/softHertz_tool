# 上位机可扩展架构重构计划

> 状态：软件重构已于 2026-07-22 实施完成；软件验证结果见 `development.md`，逐项结论见 `acceptance.md`。Windows 实际产物和真实设备验收仍未完成。

## 1. 背景（重构前基线）

重构前的 PySide6 上位机已经支持 AFDTR 三设备工作区和 AFD01_QS 工作区，但源码仍以 `code/` 下的扁平脚本为主：

- `main_qt6.py` 同时包含串口线程、协议分派、三个设备面板、工作区组装和程序入口。
- `qs_panel.py` 同时包含串口线程、速率统计、阵列控件和完整页面。
- 型号列表、页面实例化、断开逻辑和报文监视器筛选项均有硬编码。
- 模拟器与正式协议存在重复常量、校验和及解析逻辑。
- 测试依赖脚本目录和 `sys.path`，尚未形成可安装的 Python 包。

随着后续设备调试接口和界面继续增加，现有结构会扩大修改面并增加协议漂移、线程生命周期和打包回归风险。

## 2. 目标

1. 建立 `src/soft_hertz_tool` 正式 Python 包和统一模块入口。
2. 采用“按设备纵向切片 + 共享基础设施”的结构。
3. 对外分别使用真实硬件型号 **AFDT1024**（1024 发射阵列）和 **AFDR1024**（1024 接收阵列）；`AFDTR` 仅作为工作区/产品包名，`devices/afdtr1024` 及 `AFDTR1024*` 类名仅作为内部共用实现命名。
4. 分离协议、流式拆帧、驱动/串口会话、设备页面和工作区组装。
5. 使用 PyInstaller 友好的静态 workspace registry，移除主窗口的设备硬编码。
6. 保持现有 AFDTR、AFD01_QS、报文监视、模拟器、运行脚本和发布产物行为。
7. 让新增设备主要局限于一个设备目录、一个 registry 条目和对应测试。

## 3. 非目标

- 不修改受控协议的字段、端序、校验、时序和物理量算法。
- 不在本次重构中增加新的设备业务功能。
- 不引入运行时动态插件扫描或第三方插件 ABI。
- 不改变发布产物名 `SoftHertz_AFDTR_Tool`。
- 不以模拟器或 Host 测试替代真实硬件验收。
- 不主动提交 Git。

## 5. 依赖规则

1. `shared` 不导入任何具体设备模块。
2. 协议和流式拆帧模块不依赖 Qt 控件或串口对象。
3. Driver 负责串口会话、协议分派和语义状态，不创建 UI 控件。
4. Panel 只处理输入与展示，通过 Driver 的语义接口操作设备，不直接拼帧或解析帧。
5. Workspace 只组合设备页面并提供统一 `shutdown()`。
6. App 只从 registry 获取 workspace，不硬编码设备实例和逐个断开逻辑。
7. 模拟器复用正式协议常量和构帧/解析能力，避免第二份协议真值。

## 6. 实施阶段

### 阶段 A：基线与正式包

- 记录当前分支、工作区改动和 75 项测试基线。
- 增加 `pyproject.toml`、`src/soft_hertz_tool`、`__main__.py`。
- 建立资源定位、静态 registry 和通用 workspace 生命周期接口。

### 阶段 B：共享基础设施

- 提取串口配置、端口扫描和后台串口循环。
- 提取 `FrameRecord`、异步日志和报文监视器。
- 提取共享串口连接控件，避免设备页面重复端口刷新和连接状态逻辑。

### 阶段 C：设备纵向迁移

迁移顺序：

1. AFD01_QS：现有边界相对独立，作为首个样板。
2. KaUDC004A：统一使用正式 protocol builder/parser。
3. AFDT1024/AFDR1024：统一两种设备的公共行为，保留其真实协议差异和多 ID/query-2 语义。

每个设备目录至少包含 `protocol.py`、`stream.py`、`driver.py`、`panel.py`；需要时增加 `models.py` 和 `simulator.py`。

### 阶段 D：工作区、入口和兼容层

- `AfdtrWorkspace` 组合 KaUDC004A、AFDT1024、AFDR1024。
- `Afd01QsWorkspace` 组合 QS 页面。
- 主窗口遍历静态 registry，统一切换、设置记忆、报文接入和 shutdown。
- 原 `code/main_qt6.py` 等入口保留薄兼容层，避免旧脚本和现场命令立即失效。

### 阶段 E：测试、打包和文档

- 测试迁入 `tests/` 并继续兼容原测试入口。
- 更新 `run.sh`、`run.bat`、本地 PyInstaller 和 Windows workflow。
- 执行全量 pytest、py_compile、离屏 UI、模拟器持续流和本地打包验证。
- 更新 README、acceptance 和 development 记录。

## 7. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 大规模移动导致行为漂移 | 每阶段保持可运行，先加新包再将旧入口收敛为兼容层 |
| 串口线程时序变化 | 首轮优先保持现有轮询参数和信号语义；真实设备作为最终门槛 |
| PyInstaller 漏收集模块/资源 | 使用显式静态 registry、正式包导入并执行依赖分析/本地冒烟 |
| 工作区/内部共用名被误作硬件型号 | UI、日志和文档分别使用 AFDT1024、AFDR1024；`AFDTR` 与 `AFDTR1024*` 只用于工作区/内部实现 |
| 当前未提交 QS 改动丢失 | 不回退、不覆盖旧文件；先迁移当前工作区版本并持续运行 75 项回归 |
| 一次抽象过度 | 只共享已重复且稳定的串口、日志、连接和生命周期能力；设备命令保持具体实现 |

## 8. 回滚边界

- 每个阶段以独立文件集合完成，不删除当前协议原件和历史文档。
- 新入口验证通过前，旧 `code/main_qt6.py` 保持可运行。
- 任一阶段测试失败时，停止进入下一阶段，先恢复对应兼容行为。

## 9. 实施结果

- 正式实现已迁入 `src/soft_hertz_tool`，旧 `code/` 入口收敛为兼容层。
- 共享串口、报文监视、异步日志、资源定位、连接控件和生命周期契约已建立。
- KaUDC004A、AFDT1024/AFDR1024 共用实现、AFD01_QS 已形成独立设备纵向模块。
- 主窗口通过静态 registry 组装 workspace；隐藏页面会断开串口并暂停定时器。
- 发送采用有界队列和有限写超时；停止路径确认线程退出，连接代际隔离旧会话延迟信号。
- 正式测试、兼容测试、持续流、本地打包和 macOS 产物启动已通过；真实 Windows 与硬件验收保留为后续门槛。
