## 2026-09-13 阶段二：用户确认后实施

### 合同与实现

- 协议改 V2、0x20/A0 查询、46 字节状态和三段 u16 版本；负温度仍按补码解析。
- 内部 C5/C7 保持负载版本 1，既有固定/自由频率与 0x48 持久衰减回归不回退。
- 原未提交 OTA 草稿按新合同校正：空 BEGIN、无 READY/COMMIT、A4 last_result 与候选偏移。
  旧文档保留并置顶标明失效；新依据及文档摘要见 `docs/protocols/readable-notes/ka-rf-unit-v2-20260913.md`。
- OTA 流程由串口线程独占；UI 只预约启动/取消及接收信号。预约锁不跨 I/O 持有，
  普通队列拒绝、短写、断连、旧会话排队信号均有回归。
- 主站默认 1 Hz 查询、2 秒在途截止；查询与排队控制公平轮换，避免控制被查询饿死。
  扫描遇到在途请求跳过本拍，不积压迟到轨迹；OTA 占用禁用业务页并停扫描。
- 核对当前 ymodem.c，握手为 EOT/NAK/EOT/ACK+C，非旧草稿的双 ACK。
  第二 EOT 的 ACK 丢失可由 C 继续；收到 ACK 等 C 时不向等待 block0 的接收端重发 EOT。
- 重传不无限刷新无进展期限；末包后不提供撤销安装承诺。末 ACK 丢失进入静默/恢复查询；
  180 秒恢复期限、同版本未确认、旧版本/PENDING/BUSY 不立即判失败、last_result 失败显示中文原因。
- RX 控制字节先记录，再推进并发送下一包，保持监视器因果顺序；所有 TX/RX/DROP 复用 FrameRecord。
- 流解析增加 100 ms 半帧超时与坏帧滑窗重同步；模拟器只响应查询，旧版本有效请求回 BAD_VERSION。

   compileall、diff --check 均退出 0。不存在据旧草稿 446 passed 宣称新合同通过的情况。
4. Offscreen 与原生 macOS 主窗口 smoke 均退出 0；原生运行出现 IMK mach-port 诊断，未导致退出失败。

   此为 PTY 能力限制，不修改产品 460800 设置，也不宣称验证了物理线速或 DE。
