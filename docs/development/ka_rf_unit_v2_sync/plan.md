## 目标及实施顺序

1. 协议及状态：外层改 V2；0x20 空请求 / 0xA0 响应；成功载荷 46 字节，版本改三个 u16，
   温度维持 i16 补码 / 0.1 ℃。移除主动上报与设置上报频率语义，界面改本地主站查询周期。
   C5/C7 的负载 snapshot_version 仍为 1；保留原控制功能及顺序。
2. 请求调度：同一串口一个请求在途，响应或超时后才发送下一请求；普通请求默认等待 2 秒。
   OTA 原始传输及恢复期间停止普通查询、扫描与业务设置，禁止帧数据混入 YMODEM。
3. OTA 协议：BEGIN 空载荷；删除 0x22、READY、手动 COMMIT 及候选独占倒计时。
   A4 增加 last_result，成功长度为 12 或 21+名称长度；阶段为 IDLE/RECEIVING/VERIFYING/COMMITTING。
4. OTA 上传：复用现有纯状态机模块，按当前设备 YMODEM 源码核对握手、重传、双 EOT 和末尾空包；
   等设备发送 C，不由主站主动发送 C。文件使用 basename，校验本 target 版本化 App BIN 及 1..786432 字节。
   原始模式取消用 CAN；普通模式清理用 ABORT。
5. 自动安装恢复：末 ACK 只表示传输结束；停止原始发送后查询实际版本、健康状态及 last_result。
   查询约 1 秒间隔且单请求在途；目标版本且 STABLE 才能报告目标版本健康运行。
   同版本重装不宣称已证明安装；BUSY、PENDING、暂时旧版本或无响应不立即判安装失败。
   恢复等待采用明确有界期限，须容纳约 90 秒健康观察；期限届满显示“结果未确认”。
6. 集成：Driver 持有状态机和串口线程所有权；UI 仅调用语义接口，连接代际过滤旧事件，
   发送队列拒绝与串口错误明确反馈，原始 TX/RX/DROP 接入既有报文监视。
7. 同步普通协议模拟器、测试、README 和验收边界；OTA 接收端用测试桩验证，不新增可刷机设备模拟服务。
