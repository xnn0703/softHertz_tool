# 文档与代码注释同步计划

状态：已完成
完成日期：2026-07-24

## 1. 目标

以当前源码、测试、构建配置和启动脚本为事实依据，复核长期项目文档是否准确描述当前功能与边界；同时为正式代码补齐可维护的函数级说明和关键流程注释，降低后续接手与新增设备的理解成本。

## 2. 范围

- `README.md`；
- `docs/architecture`、`docs/development` 和 `docs/protocols/README.md`；
- `src/soft_hertz_tool` 中的正式模块、类、函数和方法；
- `packaging` 中的打包入口与构建函数；
- 文档与注释覆盖的自动化约束。

## 3. 非目标

- 不修改协议字段、命令、地址、校验或物理量换算；
- 不增加或删除设备功能；
- 不改变 UI 布局、串口时序、线程模型或打包策略；
- 不以主机测试替代 Windows 原生或真实硬件验收；
- 不把排查过程、协作对话或逐条操作记录写入 README。

## 4. 文档核对方法

按以下顺序确定事实：

1. 当前 `src/soft_hertz_tool` 实现；
2. `tests` 中可执行的行为约束；
3. `pyproject.toml`、启动脚本、打包脚本和 CI；
4. 受控协议原件；
5. 架构、开发和协议说明文档。

发现不一致时更新说明文档，不通过改代码来迎合已经过时的描述。涉及协议原件与实现冲突时只记录开放项，不猜测协议事实。

## 5. 注释标准

正式生产代码中的模块、类、函数和方法均应具有 docstring：

- 简单函数说明功能、输入来源和返回结果；
- 公共或复杂函数使用 `Args`、`Returns`、`Raises` 等段落说明契约；
- Qt 槽函数说明触发来源、状态变化和是否产生外部动作；
- 生命周期和线程函数说明幂等性、线程归属、超时及失败语义；
- 协议函数说明字段单位、量化、地址/命令差异和异常条件；
- 流式解析函数说明分包、粘包、坏帧恢复和返回事件；
- 行内注释只解释协议依据、并发约束或设计原因，不逐行翻译代码。

## 6. 重点流程

- 应用启动、`--smoke` 和窗口退出；
- Workspace 切换的两阶段停用/关闭；
- 串口线程的有界发送、停止与阻塞 I/O 取消；
- 快速重连时的连接代际过滤；
- AFDT1024/AFDR1024 广播、目标 ID 与双查询合并；
- AFD01_QS 高频 A0、UI 限频、阵列单请求和超时降级；
- 流式拆帧的坏数据恢复；
- `FrameRecord`、异步日志与轮转；
- 模拟器周期调度与正式协议复用；
- PyInstaller 输出清理、资源收集和稳定入口。

## 7. 实施步骤

1. 建立文档—实现—测试对照清单；
2. 修正文档中的过时目录、测试清单、命令、功能和边界；
3. 补齐生产模块、类、函数和方法 docstring；
4. 在关键状态机、并发和协议分支补充必要的原因注释；
5. 增加注释覆盖自动检查；
6. 执行编译、完整 pytest、入口冒烟和差异检查；
7. 将实际结果与开放验收边界写入实施记录。
