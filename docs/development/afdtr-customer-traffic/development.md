## 协议依据与实现

复核 TX/RX V2.2（2026-06-12）受控原件：广播 ID=0 不返回；定址查询由目标返回。
AFDT 波束 0x50，查询 0x5C/0x5F，响应 LEN=7/17；AFDR 波束 0x90，查询 0x9C/0x9F，
响应 LEN=6/17。波束间隔建议大于 2 ms，查询间隔建议 3 ms，均非物理零间隔保证。
本模式按需求允许广播波束与首查询合并写入，查询 1 返回/超时后至少满足主机 3 ms 查询间隔再发查询 2。

- `traffic.py`：纯状态机、冻结配置、单请求关联、绝对周期网格、错过时刻跳过、常量内存统计。
- `driver.py`：在所属串口线程执行状态机；运行中从 Driver 边界阻止普通发送；旧定时查询代际失效。
- `serial_thread.py`：设备无关的观察写入、截止等待及收尾扩展点；其他设备保持原发送路径。
- `traffic_panel.py` / `panel.py`：两型号简单面板、手工控件冻结、10 Hz 统计和断开后保留导出入口。
- `traffic_recorder.py`：4096 项有界异步队列，50 MiB 明细轮转；记录溢出/磁盘错误可见。
- `tests/devices/test_afdtr1024_traffic.py`：66 个参数化用例；另有三种波束模式的 POSIX 伪终端集成回归。

## 对照计划的落地说明

1. 本模式在串口线程直接调用 write，不走普通字节队列：记录 `ready_ns`、`planned_ns`、
   `write_start_ns`、`write_return_ns`；`queue_ns=null`，不伪造入队时间。
2. 零间隙批次只有一个 write 起止。原始两帧各发 FrameRecord，带相同 run_id/batch；
   明细的 `line_gap_ns=null`，分次写入另记 `host_gap_ns`。
3. 每条查询只有在地址、指令、校验、响应长度/关键字段都合法时才结束等待。
   待回复时不发周期波束、第二查询或其他手工命令。错误回复及拆帧 DROP 不解锁。
4. 慢写和查询等待都不会积累波束发送队列；周期偏差分正常与查询暂停统计。
5. 运行停止后自动生成 `summary.json` 和 `events*.jsonl`，“打开导出目录”直接打开输出位置，
   不在 UI 线程复制大文件。未新增另一套原始帧监视器。
6. 不增加波束轨迹：发送开始时页面参数的固定广播波束。随机种子和每次间隔抽样进入记录。
7. 没有事务号，因此不能严格排除下一同指令请求窗口中的旧回复；元数据明确记录该限制。

定址模式不合并任何需应答请求，零间隙表示回显/超时后无额外延迟；指定/随机间隔也从等待结束计算。

## 客户定址合包、不等待回复（本轮最终实现）

按用户纠正的实际发送行为，新增 `addressed_stream` 并设为默认。波束使用目标 ID，不等回显；
每次查询与一个定址波束合包为一次 write。两项查询分别在连续两个波束周期各发一个两帧包。
不以任何回复/超时阻塞后续周期发送，阵列侧实现未作改动。旧定址等待与广播模式保留。

应答统计与发送状态机解耦：以有界 FIFO 跟踪同类未超时请求，普通波束、状态查询、
波束参数查询分别处理。收到帧总数及三种指令类别数独立于匹配计数，迟到、重复、错误 ID
或载荷的未匹配帧不会从收到数量中消失；RX/DROP 原始报文继续记录。
同类固定报文没有事务号，FIFO 关联不能保证真实逐事务对应。每类最多跟踪 4096 个请求，
超容量立即停止并标 `tracking_complete=false`，不能静默丢失跟踪信息。
停止时尚未完成的请求记取消，超时只更新统计，不自动重发。
