# AFDT1024 / AFDR1024 客户流量模拟计划

状态：用户已确认并完成软件实现；Windows / 实机 / 线路时序待验收。日期：2026-09-10。

## 1. 目标与范围

在两个阵列面板各增加“客户流量模拟”区域，共用正式 Driver、protocol 和 stream。
电脑作为两线 RS485 唯一请求方，持续发送定址应答波束（可切换无应答广播），定期插入定址查询；
验证设备连续接收、波束与查询粘包处理及查询回复，同时验证上位机对分段回复的拆帧。
现场使用时停止其他主控发送；程序不能仲裁另一个物理主站。

首版只支持每次运行一个查询目标，不增加新工作区、日志回放、波束轨迹编辑、自动重试、
多主仲裁或手工 DE/RE 控制。不修改协议格式，也不自动使能阵列或 PA。
固定波束使用开始时页面的频率、theta、phi 快照，保持原有频率量化。
这是发送节奏模拟，不宣称重现客户轨迹或客户实测速率。

## 2. 面板参数

| 参数 | 首版默认 / 约束 |
| --- | --- |
| 波束模式 | 默认定址非等待合包（第 8 节）；保留定址等待（第 7 节）和无应答广播 |
| 波束周期 | 10 ms，正数 |
| 查询周期 | 1000 ms，指一轮所选查询的计划周期，正数 |
| 查询类型 | 默认两项；可选状态、波束参数、两项 |
| 查询地址 | AFDR1024：0x9C / 0x9F；AFDT1024：0x5C / 0x5F，界面随型号显示 |
| 查询目标 | 独立单目标 ID，默认 0x01，范围 0x01～0x7F；不继承页面广播选择 |
| 波束与首条查询间隔 | 默认零间隙；可选指定间隔、随机间隔 |
| 指定间隔 | 默认 1 ms，非负 |
| 随机间隔 | 默认均匀分布 0～5 ms；可设上下限，记录本次种子与每次抽样 |
| 运行时长 | 默认 1 min，正数，可输入小数 |
| 每条查询回复超时 | 默认 100 ms，正数，无自动重发 |

1 min、100 ms、1 ms、0～5 ms 是本方案提出的初值，不是设备保证值。
参数在开始前校验并冻结；运行中提供停止、当前阶段、剩余时长及统计导出。
统计展示不高于 10 Hz，不逐波束追加业务文本日志；原始帧仍进入统一报文监视及异步日志。

## 3. 广播模式调度与请求应答合同（定址模式见第 7 节）

1. 在现有串口所属线程执行状态机；UI 只发送开始/停止请求、展示快照。
2. 使用单调时钟和绝对截止时间，普通波束 ID 固定为 0x00，不等待回显。
3. 查询到期后在下一波束时刻开始一轮：广播波束 → 间隔 → 查询 1 → 等回复或超时。
   只选波束参数时，它就是本轮查询 1。零间隙将完整波束帧和完整查询帧拼成一个 write 调用。
4. 若选择两项，查询 1 完成或超时后再发送查询 2，再等待匹配回复或超时。
   查询 2 前不额外发波束；两次查询之间遵守受控协议最小指令间隔（已复核原件，为建议间隔），
   不把两条需应答的查询合并写出。首版按至少 3 ms 主机保护间隔实现。
5. 从本轮广播开始到最后一条查询结束，暂停所有周期波束和本串口其他业务发送。
   指定/随机间隔期间也不能插入其他帧。
6. 结束后回到原绝对周期网格，跳过已经错过的波束/查询时刻，分别累计跳过数。
   不补发积压波束，不积压下一轮查询。查询周期不足以容纳等待时，实际查询频率会降低。
7. 同时只允许一个待回复查询。只有当前连接/运行代际中、目标 ID 与指令匹配、
   帧及响应载荷合法的回复才能完成等待；普通波束、查询自身回环、错误 ID/指令、坏帧不能解锁。
8. 超时继续本轮下一查询或恢复波束，不自动重试。空闲期间迟到/重复回复记异常。
   协议没有事务序号：同 ID 同指令的旧回复若恰落入下一请求窗口，无法严格区分，报告须保留此限制。
9. 到达运行时长或主动停止立即禁止新发送；正在等待的查询按取消记录，不伪记超时或成功。
   已提交操作系统的字节不能撤回。停止确认后才解锁手工发送；连接中断、隐藏、退出复用现有停止路径。

## 4. 串口所有权与实现位置

实施前 `SerialThread._flush_tx()` 每轮最多写出 32 个队列项，没有写入时间/字节数事件；
`AFDTR1024Driver.query_status()` 用 QTimer 固定间隔投递，不能承担本功能的等待应答合同。

- `devices/afdtr1024/traffic.py`：纯状态机、配置、统计与可注入单调时钟/随机源。
- `devices/afdtr1024/driver.py`：语义开始/停止入口、状态机执行、回复关联、运行代际。
- `devices/afdtr1024/panel.py` 及必要的设备内 UI 文件：简单配置区域和限频展示。
- `shared/transport/serial_thread.py`：仅增加设备无关的循环调度/写入结果扩展点，保持其他设备默认行为。
  不在 shared 导入阵列逻辑，不另开一个线程操作同一 pyserial 对象。
- 开始运行时串行取得发送所有权：取消旧查询定时回调，确认旧队列及未完成写入已处理后开始；
  无法确认空闲则拒绝开始并说明原因。运行期间 Driver 拒绝普通业务发送，不能仅靠 UI 禁用按钮。
- 根据下一个发送/超时截止时间采用有界等待，不能依赖 UI 定时器精度；持续读数据时也检查截止时间。
- 短写、写异常、队列失败必须记录，停止本轮运行，不当成已完成发送，也不盲目补写整包。

## 5. 计时与记录口径

每次运行记录 run_id、连接代际、型号、端口参数、完整配置和时钟基准；使用单调 ns 计算差值，
墙钟仅用于与外部日志关联。指标须来自真实写入调用与接收解析事件，不从 QTimer 次数推算。

| 记录 | 定义 |
| --- | --- |
| 计划 / 入队 / write 开始 / write 返回 | 分别记录；已入队不等于已经发送 |
| 写入结果 | 请求字节数、返回字节数、成功/短写/异常、write 批次 ID |
| 周期偏差 | 波束 write 开始减计划时刻，以及相邻波束 write 开始间距；区分查询暂停与正常周期 |
| 查询前间隔 | 配置/抽样间隔与主机观测间隔分列；分次 write 时记录前次返回至查询开始的差值 |
| 合并写入 | 两条 FrameRecord 保留各自原始帧并关联同一批次；只有批次 write 起止时间 |
| 接收 / 回复延迟 | 在串口线程记录 read 返回和完整合法匹配帧解析时刻；延迟按解析完成减查询 write 返回计算 |
| 查询超时起点 | 查询所属 write 完整成功返回；与 UI 投递时间无关 |
| 结果计数 | 完整写入的波束/查询数、匹配回复、超时、取消、异常回复、DROP、发送失败和跳过周期数 |

合并写入模式的帧内实际间隔记“未测”，不得填成实测 0 ms；主机 write 返回也不等于最后停止位上线路。
需要时可依据波特率估算串行化时长，但必须标“估算”，不混入实测统计。
首版适配具有自动方向切换能力的两线 RS485 转换器；实际 DE 释放、线路间隔与响应周转用逻辑分析仪验收。

明细使用有界异步记录，提供 JSONL 明细及 JSON 汇总导出（含计时口径、丢失记录数和停止原因）。
复用统一原始帧日志；不引入第二套原始帧监视器。若明细记录过载，明确标记统计证据不完整。
内存不得随运行时长无限增长。

## 6. 拆包粘包与验收路线

生产发送默认完整波束，零间隙将波束+首查询合并一次 write。自动化测试把这批字节按任意边界切分、
逐字节及整批送入正式 stream + 现有模拟器，验证只对查询应答。
对回复同样覆盖分段、拼接异常帧、坏校验后恢复，证明上位机只被有效匹配回复解锁。
一次 write 不能保证对端一次 read，也不能保证物理零间隔。

受控基线：TX/RX V2.2（2026-06-12）原件；已在实现时复核原件中的广播规则、波束地址、查询地址、响应长度与建议间隔。
目标环境：macOS 主机测试、Windows 源码/EXE、两线 RS485 的 AFDT1024/AFDR1024 实机。

实施顺序：确认本计划 → 原件复核与现有测试基线 → 状态机及回归测试 → 串口写入观测与所有权 →
面板 → 模拟器闭环 → README/开发记录更新 → 按 acceptance 逐项 review。
Windows、实机及逻辑分析仪证据未取得时保持未验收，不以 pytest 替代。

## 7. 已确认的定址波束应答调整（2026-09-10）

用户要求波束按指定 ID 下发并等待回复。本次将“定址应答”设为默认，保留广播模式供原有场景回归。
波束与查询共用目标 ID 和回复超时；定址波束必须收到原帧完整回显才算匹配，普通接收数据不能解锁。
定址模式任何时刻只允许一个应答请求：波束 → 等回显/超时 →（查询到期时）间隔 → 查询 → 等回复。
零间隙指回显/超时结束后不额外等待，不得把需要回复的波束与查询合并 write。
指定/随机间隔同样从波束回显/超时结束计时；明细区分总主机间隔与应答结束后的间隔。
波束回复、超时、取消、延迟与查询统计分列。等待期间跳过波束周期，不积压补发。
无事务号且波束内容固定，因此无法严格排除迟到的相同波束回显；通过定址应答不替代广播零间隙测试。
本节覆盖前文的“默认广播”描述，广播模式保留其原行为。

## 8. 客户不等待应答的合包测试（本轮用户明确要求）

新增并默认选择“定址应答＋零间隙，不等待回复”：发送逻辑与应答统计解耦。
普通波束按目标 ID 发送，不等回显；查询到期时完整波束＋一条完整查询一次 write。
选择两项查询时分别在连续两个波束时刻各发一个两帧包，不以第一查询回复触发第二查询。
回复无论早晚都不影响下一发送时刻。原有定址等待、广播模式保留。
此模式固定零间隙，超时参数仅用于后台统计；不承诺阵列侧可处理这些流量。
统计原始有效 RX 总帧数、波束回显/状态回复/波束参数回复收到数量，再分别统计匹配、超时、异常。
用有界 FIFO 关联尚未超时的同类请求，缺少事务号时不宣称一一对应；超出跟踪容量立即停止并标明统计未完整。
停止时取消待跟踪请求，不当作超时。仍沿绝对周期网格跳过错过时刻，不积压发送。
