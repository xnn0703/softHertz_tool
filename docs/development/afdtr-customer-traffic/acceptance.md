## 目标平台与物理验收

- [ ] Windows 原生 EXE 面板打开、开始/停止、导出及串口关闭正常，记录产物版本与系统信息。
- [ ] 每型号单主机双向连接两线 RS485，记录设备/固件、实际 ID、波特率及转换器型号。
- [ ] 零/指定/随机间隔分别运行；原始抓包确认广播无回复、查询定址、等待中无后续请求。
- [ ] 逻辑分析仪核对波束末停止位至查询首起始位、DE 释放及回复周转，区分软件设定与线路实测。
- [ ] 对无回复设备测试超时恢复；缺少硬件故障注入条件的项目明确标记未验收。
- [ ] 默认配置至少 10 min 实机运行，记录发送、回复、超时、异常、周期分布及记录丢失数。
- [ ] 不将同指令迟到回复的关联限制隐藏为严格事务保证，不把软件 write 返回当作物理发送完成。

物理时序不预设“0 ms”通过门槛；报告仪器分辨率与实测范围。软件完成与实机验收分开结论。

## 定址应答补充验收

- 默认波束使用目标 ID（TX/RX 各覆盖），广播模式仍发送 ID=0。
- 定址波束 write 后禁止任何后续波束或查询，直至完整原帧回显或超时。
- 错误 ID、指令、内容、校验及分段不完整的回显均不解锁。
- 定址模式零/指定/随机间隔均在应答等待结束后应用，不合并需应答报文。
- 波束应答/超时/取消/延迟与查询统计分列；慢回复后跳过过期周期。
- 两模式各通过正式 Driver + stream + simulator 的 PTY 闭环；停止和明细导出仍可用。

## 客户非等待合包模式验收

- TX/RX 均在无任何回复时继续发波束与到期查询，合包恰为定址波束＋单条查询的一次 write。
- 选择两查询时各占一包，无回复也发送第二包；超时只影响统计。
- 回复乱序、分段/粘包、缺失、迟到、重复、错误 ID/载荷分别计数，原始 RX 数量不因匹配失败消失。
- 超时、取消、未跟踪容量错误与发送失败可观察；计数与实际 write 相符。
- 三种模式回归及新模式双型号 PTY 闭环通过。
